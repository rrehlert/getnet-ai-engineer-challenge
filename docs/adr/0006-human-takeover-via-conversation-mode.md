# Human takeover as a Conversation Mode, not a graph interrupt

Human-in-the-loop here means an Operator taking over a Conversation and talking to the Merchant directly. We model it as a Mode on the Conversation (`bot`, `waiting_human`, `human`, `closed`) checked by the API: outside `bot` Mode the graph doesn't run and Turns are just stored for the other side. We rejected LangGraph `interrupt()`/resume for this: a takeover spans many Turns from both sides, so one graph run would stay paused for the whole takeover, every message would become a resume, the API would still need to know whether the thread is paused (the Mode, hidden in a checkpointer), and delivering Operator replies would still need storage outside the graph. `interrupt()` fits a single pause (approve or reject an Agent action) and remains the plan for approval-style HITL once tools can change data.
